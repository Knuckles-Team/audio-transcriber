# CONN-AUDIO-TRANSCRIBER — Requirements

Governing spec: [spec.md](spec.md).

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-AUDIO-TRANSCRIBER-R001` | **Read-only engine health.** The connector must expose `health_check` with the read-only annotation in `audio_transcriber/mcp_server.py`. The tool must report the importable backends, ffmpeg presence, the default model and the transcription directory without a model load. Caller chain: The `audio-transcriber-mcp` console script runs `scion_sdk.cli:serve`, which builds the server from `audio_transcriber/__init__.py::connector` (tools=`audio_transcriber.mcp_server`) and serves `audio_transcriber/mcp_server.py::register_misc_tools.health_check`, which returns `audio_transcriber/mcp_server.py::engine_health`. Shape: `engine_health` in `audio_transcriber/mcp_server.py` reads importable Whisper backends, ffmpeg presence, default model and `DEFAULT_TRANSCRIBE_DIRECTORY` without constructing `AudioTranscriber`; the tool is registered with `readOnlyHint` true and needs no new helper. | `tests/test_read_only_health.py` must show: the tool is listed read-only, reports the engine fields without a model load, and reports DEGRADED when no backend is importable. Test: `tests/test_read_only_health.py::test_health_check_is_listed_read_only`. |
| `CONN-AUDIO-TRANSCRIBER-R002` | **Fleet name.** `pyproject.toml` declares `audio-transcriber-mcp` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `audio-transcriber-mcp`. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. Caller chain: The `audio-transcriber-mcp` console script in pyproject.toml runs `scion_sdk.cli:serve`, which loads the single `scion_sdk.connector` entry point `audio-transcriber-mcp = audio_transcriber:connector` defined in `audio_transcriber/__init__.py::connector`. Shape: The name is declared once in the pyproject.toml entry point and repeated as `server="audio-transcriber-mcp"` in `audio_transcriber/connector_sources.py::SOURCES`; the content pack and fingerprints derive from the SDK connector identity (`scion_sdk.connector_identity.connector_name`), so no extra helper is needed. | Every connector name in the package is `audio-transcriber-mcp`. |
| `CONN-AUDIO-TRANSCRIBER-R003` | **Microphone extra.** `pyproject.toml` declares the `microphone` optional extra with `pyaudio`, so `pip install audio-transcriber[microphone]` installs microphone recording. The PR pipeline installs the extras without `microphone` (the `sync-args` input of the shared pipeline), because `pyaudio` needs PortAudio headers that CI runners lack. Proving test: `tests/test_microphone_extra.py`. Caller chain: A user runs `pip install audio-transcriber[microphone]`, which resolves the `microphone` extra in pyproject.toml; the `audio-transcriber` console script (`audio_transcriber.audio_transcriber:main` entry `audio_transcriber()`) then records through `audio_transcriber/audio_transcriber.py::AudioTranscriber.record`. Shape: pyproject.toml `[project.optional-dependencies] microphone = ["pyaudio>=0.2.14"]` plus the PR workflow `sync-args` input of the shared pipeline; pyaudio is imported lazily in `AudioTranscriber`, so no code change is needed. | The `microphone` extra lists `pyaudio`; the PR workflow passes `sync-args` that omit it. Test: `tests/test_microphone_extra.py::test_microphone_extra_is_declared`. |
| `CONN-AUDIO-TRANSCRIBER-R004` | **Meeting segment tools.** Subsystem: audio-transcriber served tools (new spec in audio-transcriber). Register `meeting_segment_append`, `meeting_segment_correct`, `meeting_finalize` and `meeting_get_final` in `audio_transcriber/mcp_server.py` through `scion_sdk.meeting.tools.register_meeting_tools`. The tools take `MeetingSegment` fields and return engine receipts unchanged. They carry the caller tenant from the authenticated context and never from arguments. The tool `transcribe_audio` stays single-shot. Depends on: SCION-SOURCE-INGEST-R014.3. Caller chain: (planned) The `audio-transcriber-mcp` console script runs `scion_sdk.cli:serve` and loads `audio_transcriber/__init__.py::connector`; the four meeting tools will be registered from `audio_transcriber/mcp_server.py` through `extra_registrations` like the existing `register_prompts` hook, and no meeting code exists in the package today. Shape: Add a `RegistrationContext` hook in `audio_transcriber/mcp_server.py` that calls `scion_sdk.meeting.tools.register_meeting_tools(context.server)` and add it to `extra_registrations` in `audio_transcriber/__init__.py`; `transcribe_audio` stays unchanged. | Test: `tests/test_meeting_tools.py::test_tools_listed_with_hints_and_tenant_from_context` (L3). A served test lists the four tools and asserts that a tenant argument is ignored. |
