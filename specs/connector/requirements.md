| `CONN-AUDIO-TRANSCRIBER-R001` | **Read-only engine health.** The connector must expose `health_check` with the read-only annotation in `audio_transcriber/mcp_server.py`. The tool must report the importable backends, ffmpeg presence, the default model and the transcription directory without a model load. Caller chain: The `audio-transcriber-mcp` console script runs `scion_sdk.cli:serve`, which builds the server from `audio_transcriber/__init__.py::connector` (tools=`audio_transcriber.mcp_server`) and serves `audio_transcriber/mcp_server.py::register_misc_tools.health_check`, which returns `audio_transcriber/mcp_server.py::engine_health`. Shape: `engine_health` in `audio_transcriber/mcp_server.py` reads importable Whisper backends, ffmpeg presence, default model and `DEFAULT_TRANSCRIBE_DIRECTORY` without constructing `AudioTranscriber`; the tool is registered with `readOnlyHint` true and needs no new helper. | `tests/test_read_only_health.py` must show: the tool is listed read-only, reports the engine fields without a model load, and reports DEGRADED when no backend is importable. Test: `tests/test_read_only_health.py::test_health_check_is_listed_read_only`. |

| `CONN-AUDIO-TRANSCRIBER-R005` | **Transcript list and get by recording id and date.** Subsystem: audio-transcriber served tools. Register two read-only tools in `audio_transcriber/mcp_server.py` through a new `register_transcript_tools(mcp)`, each with the read-only annotation (`readOnlyHint` true, `destructiveHint` false, `idempotentHint` true, `openWorldHint` false). `list_transcripts(recording_id: str | None = None, date_from: str | None = None, date_to: str | None = None, limit: int = 100)` returns `{items: [{id: str, date: str, text: str}], truncated: bool}`. `get_transcript(recording_id: str)` returns `{id: str, date: str, text: str, segments: [{start: float, end: float, no_speech_prob: float}]}`. A transcript is the JSON export `<directory>/<id>.json` that `AudioTranscriber.export` writes (`audio_transcriber/audio_transcriber.py:440`), where `directory` is `DEFAULT_TRANSCRIBE_DIRECTORY` (`audio_transcriber/mcp_server.py:57`) and `id` is the file stem, also called the recording id. `date` is the UTC calendar date of the file's modification time, as `YYYY-MM-DD`. `text` joins the segment texts with one space; `start`, `end` and `no_speech_prob` are copied from the stored segments unchanged. `list_transcripts` filters by `recording_id` (exact match) and by the inclusive date range `date_from` to `date_to` (each `YYYY-MM-DD`, either optional), sorts by `date` descending then `id` ascending, and returns at most `limit` items (`limit` is an integer from 1 to 500, default 100; `truncated` is true when more matched). The tools read files only: they write nothing, load no model and make no network call. Refusals, each returned as an error whose first token is the code: `INVALID_RECORDING_ID` when `recording_id` is empty, longer than 255 characters, contains a path separator or equals `.` or `..`; `INVALID_DATE_RANGE` when a date does not parse as `YYYY-MM-DD` or `date_from` is after `date_to`; `LIMIT_OUT_OF_RANGE` when `limit` is outside 1 to 500; `TRANSCRIPT_NOT_FOUND` when `get_transcript` finds no `<id>.json`; `TRANSCRIPT_UNREADABLE` when the file is not valid JSON or has no `segments` list. A refusal changes nothing. Knobs: none. Writes: none. Depends on: `CONN-AUDIO-TRANSCRIBER-R001`. Caller chain: (planned) The `audio-transcriber-mcp` console script runs `scion_sdk.cli:serve` and loads `audio_transcriber/__init__.py::connector`; `register_transcript_tools` is added beside `register_prompts` as a second `extra_registrations` hook in `audio_transcriber/__init__.py` (`:19`), which registers the two tools; each tool reads the JSON files under `DEFAULT_TRANSCRIBE_DIRECTORY`. No transcript listing code exists in the package today. Shape: add `register_transcript_tools` and the helper `load_transcript(path) -> dict` to `audio_transcriber/mcp_server.py`, and add `_register_transcripts(context)` to `extra_registrations` in `audio_transcriber/__init__.py`; the helper reuses the `json` export format of `AudioTranscriber.export` and adds no new file format. | Test: `tests/test_transcript_listing.py::test_list_and_get_by_recording_id_and_date` (planned) (L3) lists both tools read-only through the served connector, filters by id and by date range, checks ordering, `limit` and `truncated`, and reads one transcript with its segments. `tests/test_transcript_listing.py::test_refusals_write_nothing` (planned) (L3) asserts each of the five refusal codes and that the directory is unchanged. Consumer: medulla row MEDULLA-MEDIA-VOCAB-R028. |
