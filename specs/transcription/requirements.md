| `TRANSCRIBE-R002.1` | **Typed tool and result.** `transcribe_speech(artifact_b64, digest, media_type, language?, task?, word_timestamps?, diarize?)` is a typed tool (no `action` or `params_json` routing). Its description carries the `Capability: speech-to-text` line and its tags carry `speech-to-text`, so callers discover it by contract, not by server name. It returns `SpeechTranscript{schema_version='speech-transcript/1', status ok|refused, refusal_code, source_digest, media_type, text, language, language_probability, duration_s, segments[{start_ms,end_ms,text,speaker,words[]}], diarization{requested,supported,reason}, converted, model, backend}`. Refusals are typed and carry no text: `INVALID_ARGUMENT`, `DIGEST_MISMATCH`, `MEDIA_TOO_LARGE`, `MEDIA_TOO_LONG`, `UNSUPPORTED_MEDIA`, `TRANSCRIPTION_FAILED`; caller errors make zero backend calls. Limits: `SPEECH_MAX_BYTES` (default 25 MiB), `SPEECH_MAX_DURATION_S` (default 600). Caller chain: the `audio-transcriber-mcp` console script runs `scion_sdk.cli:serve`, which loads `audio_transcriber/__init__.py::connector` and runs `register_speech_tools` in `audio_transcriber/mcp_server.py`; the served tool `transcribe_speech` calls `audio_transcriber/speech_contract.py::transcribe_speech`, which calls `AudioTranscriber.transcribe` in `audio_transcriber/audio_transcriber.py`. Production consumer: arbora's modality seam (ARBORA-OPS-R899). | Test: `tests/test_speech_contract.py::test_transcribe_speech_tool_is_registered_typed_and_returns_the_contract`, `tests/test_speech_contract.py::test_caller_errors_are_typed_refusals_with_zero_backend_calls`, `tests/test_speech_contract.py::test_size_and_duration_limits_refuse`, `tests/test_speech_contract.py::test_backend_failure_never_fabricates_text`. |

| `TRANSCRIBE-R002.3` | **ffmpeg format conversion in the image.** `pyproject.toml` `[tool.pipelines.container] runtime_apt` installs `ffmpeg` in the rendered runtime image. Input that is not 16 kHz mono PCM WAV is converted to it with ffmpeg (`speech_contract.convert_to_wav`) before inference, so Ogg/Opus voice notes, WebM, M4A and MP3 transcribe the same on every backend; undecodable media refuses `UNSUPPORTED_MEDIA`. Without the binary the backend's own decoder gets the original file. Caller chain: the `audio-transcriber-mcp` console script runs `scion_sdk.cli:serve`, which loads `audio_transcriber/__init__.py::connector` and runs `register_speech_tools` in `audio_transcriber/mcp_server.py`; the served tool `transcribe_speech` calls `audio_transcriber/speech_contract.py::transcribe_speech`, which calls `AudioTranscriber.transcribe` in `audio_transcriber/audio_transcriber.py`. Production consumer: arbora's modality seam (ARBORA-OPS-R899). | Test: `tests/test_speech_contract.py::test_non_canonical_audio_is_converted_with_ffmpeg`, `tests/test_speech_contract.py::test_undecodable_media_without_ffmpeg_falls_through_and_with_ffmpeg_refuses`. |
| `TRANSCRIBE-R002.4` | **The faster-whisper backend loads and decodes on a torch-free, current-PyAV install.** `FasterWhisperBackend.load_model` picks the device from CTranslate2 (`_ctranslate2_device`), not torch, so a torch-free install no longer reads as "faster-whisper not found". `FasterWhisperBackend.transcribe` hands faster-whisper 16 kHz mono float32 samples decoded by the ffmpeg binary (`_decode_with_ffmpeg`), because faster-whisper's own decoder passes `metadata_errors` to `av.open`, which current PyAV rejects. Caller chain: `transcribe_speech` and `transcribe_audio` in `audio_transcriber/mcp_server.py` call `AudioTranscriber.transcribe`, which calls `FasterWhisperBackend.load_model` and `FasterWhisperBackend.transcribe` in `audio_transcriber/audio_transcriber.py`. | Test: `tests/test_speech_contract.py::test_device_probe_needs_no_torch`, `tests/test_speech_contract.py::test_faster_whisper_gets_ffmpeg_decoded_samples`. |
